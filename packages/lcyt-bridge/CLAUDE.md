# `packages/lcyt-bridge` — Production Control Bridge Agent (v0.3.0)

Standalone agent that connects to the LCYT backend via SSE and relays commands to physical AV hardware (AMX controllers, Roland mixers) over TCP, and — since `plan_ai_model_registry.md` — to a local AI model endpoint (e.g. self-hosted Ollama) unreachable from the backend directly. Designed to run on-site where the hardware/model is located.

**Entry:** `src/index.js` (shebang, runs with `node src/index.js` or as a compiled binary)
**Config:** `.env` file in the same directory as the executable (or `process.env`); optionally also a `security.local.yaml` in that same directory (see `local-security-floor.js` below and `security.local.yaml.example`)

**Required env vars:**
| Variable | Purpose |
|---|---|
| `BACKEND_URL` | Base URL of the LCYT backend |
| `BRIDGE_TOKEN` | Authentication token from `POST /production/bridge/instances` |

**Source files (`src/`):**
- `index.js` — Entry point. Loads config (`loadConfig()` returns `{ backendUrl, token, exeDir }` — `exeDir` via `resolveExeDir()`, the directory the `.env`/`security.local.yaml` live in, whether running via `node src/index.js` or as a `pkg`-compiled exe), starts the Bridge, optionally shows system tray icon. Logs the local security floor's initial load result (rule counts, or a loud error if `security.local.yaml` is present but malformed) right after constructing the `Bridge`, then whether hot reload is active; a shared `logFloorSummary(summary, { reload })` helper re-logs the same shape on every later `security:floor-reloaded` event from the `Bridge` (edit/create/delete/recovery), so the console reflects the file's current state without a restart.
- `bridge.js` — `Bridge` class (`EventEmitter`). Connects to `GET /production/bridge/commands?token=xxx` SSE stream. Dispatches `tcp_send`/`atem_switch`/`http_request`/`obs_switch` commands, plus `model_call` (AI inference relay, `plan_ai_model_registry.md`): fetches an optional `sourceUrl` itself (raw image bytes never cross the SSE command channel — the bridge pulls, the backend never pushes binary down the command stream) via `_modelCall()`, then POSTs to a local model `endpoint` (e.g. Ollama's `/api/generate`) with base64 `images`/JSON `format` as appropriate. Reports results via `POST /production/bridge/status`. Exponential-backoff reconnect (5s → 60s max). **Security (defense in depth, two independent local layers, either can block — OR, not override):** before dispatching any of `tcp_send`/`atem_switch`/`obs_switch`/`http_request`/`model_call`, `_checkSecurity()` consults (1) a local `SecurityPolicy` instance — rules *fetched from* the backend, a second opinion on `packages/plugins/lcyt-production/src/bridge-manager.js`'s authoritative `sendCommand()`-side check, not independent of it — and (2) a local `LocalSecurityFloor` instance — an optional, deployer-controlled `security.local.yaml` read from local disk only, the one layer the backend itself cannot influence even if compromised. `SecurityPolicy`'s rules are fetched via `GET /production/bridge/security-rules/for-agent?token=xxx` — fired immediately on `start()` (no need to wait for the SSE `connected` event; the endpoint resolves the instance from the token alone), refetched on a `rules_updated` SSE push and a 60s fallback timer; a monotonic sequence number in `_fetchSecurityPolicy()` guards against a slower, older fetch clobbering a newer one. **Fails closed**: any secured command arriving before `SecurityPolicy`'s *first* successful fetch is rejected locally (`'bridge security policy not yet loaded'`); a later refetch failure keeps using the last known-good policy instead of clearing it. Constructing with a `localPolicyDir` also starts `LocalSecurityFloor.watch()` (hot reload); `destroy()` stops it. `localSecurityFloorSummary()` exposes `{ present, loadError, ipRuleCount, commandRuleCount }`; `localSecurityFloorWatching()`/`localSecurityFloorWatchError()` expose whether hot reload is actually active; the `security:floor-reloaded` event fires (with the fresh summary) on every hot reload.
- `security-policy.js` — `SecurityPolicy`: the backend-synced rule cache/evaluator described above. `checkIp(host, port)`/`checkCommand(payload)`, same allow/deny precedence as the backend's `bridge-security.js` (deny always wins; an allow-list, if populated, switches that rule kind to default-deny) — logic is intentionally duplicated rather than shared as a package dependency (same "copy, keep in sync" convention as `packages/plugins/lcyt-production/src/mediamtx-client.js`). Also exports `matchesHostPattern`/`matchesCommandPattern`/`isValidHostPattern`/`isValidCommandPattern`, reused in-package by `local-security-floor.js` rather than copied a third time.
- `local-security-floor.js` — `LocalSecurityFloor`: loads and evaluates the optional `security.local.yaml` deny-only floor. `load(dir, filename?)` reads it synchronously; `watch(onReload?)` then starts hot reload — `fs.watch()` on the *directory* (not the file, so a file that doesn't exist yet is still picked up once created, and rename-based atomic saves are caught reliably), debounced 250ms, calling `load()` again and invoking `onReload(summary())` on every settle. Edits, creates, and deletes all take effect without a bridge restart — chosen specifically because a restart is not something every deployment (e.g. a bridge on a headless Raspberry Pi next to the hardware) can casually rely on. `close()` stops watching (called from `Bridge.destroy()`); `isWatching()`/`watchError()` expose whether it's actually active (a failed `fs.watch()` setup — e.g. an unusual filesystem — degrades to load-once-at-startup rather than throwing). `parseLocalPolicyDocument(doc)` validates structure (`{ rules: [{ kind: 'ip'|'command', pattern, description? }] }`) and each pattern (via `security-policy.js`'s validators) up front, throwing a specific error for anything malformed. **Fails closed on a malformed file**: `checkIp()`/`checkCommand()` return `{ allowed: false }` for *everything* while `loadError()` is set, rather than silently ignoring a broken "last line of defense" — a deployer who believes they've locked something down should never be wrong about that, and a bad edit takes effect (fails closed) on the very next reload, not just at the next startup. No file present → no restriction added (absence changes nothing). See `packages/lcyt-bridge/security.local.yaml.example` and the README's "Local security floor" section.
- `tcp-pool.js` — `TcpPool`: manages a pool of named TCP connections. Reconnects on drop.
- `atem-pool.js` — `AtemPool`: pooled Blackmagic ATEM connections (via the `atem-connection` UDP protocol) for `atem_switch` commands — persistent connections, reconnect logic, program input switching.
- `obs-pool.js` — `ObsPool`: pooled OBS WebSocket connections for `obs_switch` scene switching, built on the shared `OBSClient` abstraction from `packages/plugins/lcyt-production/src/obs-client.js`.
- `tray.js` — Optional system tray icon (for packaged desktop use).

`Bridge.status()` includes per-pool state: `tcp`, `atem`, and `obs` connection arrays.

**Build as standalone executable** (using `pkg`):
```bash
npm run build:win    # → dist/lcyt-bridge.exe  (Windows x64)
npm run build:mac    # → dist/lcyt-bridge-mac  (macOS x64)
npm run build:linux  # → dist/lcyt-bridge-linux (Linux x64)
```

**Docker deployment mode:** a second, simpler mode alongside the pkg-compiled desktop executable — a plain Node container (`docker/lcyt-bridge/Dockerfile`, just `node src/index.js`; `tray.js`'s import is already gracefully optional). `docker/lcyt-bridge-ollama/` compose-networks this with an `ollama/ollama` container on a private network never exposed to the host — the bridge is the only thing that can reach it, which matters specifically because Ollama has no built-in authentication. See that directory's README. Nothing about either mode is exclusive: the same bridge instance can relay real AMX/Roland/ATEM/OBS TCP commands (with real LAN access) while also dispatching `model_call` against a Docker-internal Ollama.

## Test Coverage

**Test files:** `test/bridge.test.js` (includes `model_call` dispatch: successful POST + parsed body, `sourceUrl` fetch + base64 image attachment, JSON output mode, source-fetch failure, missing-endpoint error; a local-security-enforcement describe block for `SecurityPolicy` — blocked commands never reach `TcpPool`/`_httpRequest`, fail-closed before the first policy load; a `_fetchSecurityPolicy()` wiring block covering the `connected`/`rules_updated` SSE events and stale-cache-on-refetch-failure; and a `LocalSecurityFloor` wiring block — backward-compatible when `localPolicyDir` is omitted, loads at construction time, blocks a command the backend-synced `SecurityPolicy` would have allowed [and vice versa, confirming the two layers are genuinely OR'd], a malformed file blocks everything with a message distinguishable from `SecurityPolicy`'s own block message, and — the case a broken short-circuit could most plausibly slip through — the local floor's deny still blocks an IP/command the backend's own `SecurityPolicy` is in allow-list mode for [i.e. an explicit backend `allow` rule ("allow only this") does not bypass the floor check, while a different target the floor doesn't deny still passes through]; plus a hot-reload wiring block — `localSecurityFloorWatching()` true after construction and false after `destroy()`, an edited file blocks a target on the very next `_handleCommand()` call with no new `Bridge` instance, `security:floor-reloaded` fires with the fresh summary, and `destroy()` actually stops the watcher [a later edit is never picked up]), `test/tcp-pool.test.js`, `test/atem-pool.test.js` (includes its own `atem_switch` dispatch + security-policy-primed describe block), `test/security-policy.test.js` (`SecurityPolicy`'s own allow/deny precedence, fail-closed-until-loaded, CIDR/port pattern matching), `test/local-security-floor.test.js` (`LocalSecurityFloor`'s own: no-file-present no-op, valid-file deny matching across both rule kinds, fail-closed on every flavor of malformed file [bad YAML, non-mapping top level, non-list `rules`, unknown `kind`, invalid pattern, non-string `description`], reload-replaces-not-merges semantics including recovery once a fixed file is reloaded, `summary()`, `parseLocalPolicyDocument()`'s structural validation directly, and a `watch()` hot-reload block — reload on edit/create/delete, `onReload` callback payload, fail-closed then recovery across two live edits, `close()` actually stopping further reloads, a redundant second `watch()` call being a no-op, and an unrelated file in the same directory not triggering a reload).

**Covered:** Bridge SSE connection/reconnect, TCP pool, command dispatch (`tcp_send`, `atem_switch`, `model_call`), heartbeat, event forwarding, local security-policy enforcement and fetch/refresh wiring, the local security floor file and its wiring into `Bridge._checkSecurity()`.

**Gaps (Medium):**
- `tray.js` (105 LOC) — system tray icon/menu/exit handler (desktop only).
- `src/index.js` (107 LOC) — `BACKEND_URL`/`BRIDGE_TOKEN` validation, `.env` loading, SIGTERM shutdown.

---

This agent talks to `packages/plugins/lcyt-production`'s `BridgeManager` (see `packages/plugins/lcyt-production/CLAUDE.md`) over the `/production/bridge/*` routes. `BridgeManager.sendCommand()`'s per-call `timeoutMs` override (120s default for `model_call`, vs. 10s for everything else) lives on that side, as does the authoritative per-bridge TCP-command/target-IP allow-deny check (`bridge-security.js`) this agent's own `security-policy.js` duplicates locally.
